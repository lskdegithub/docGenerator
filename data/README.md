# 测试数据目录使用说明

## 📁 目录结构

```
data/
├── 001-test-metric/                    # 测试指标1
│   ├── 001-metric.yaml                # 指标定义（三级标题内容）
│   ├── 001-module/                    # 该指标涉及的模块1
│   │   ├── metadata.yaml              # 模块元数据（四级标题内容）
│   │   ├── 001-item1/                 # 测试项1
│   │   │   ├── plan.yaml              # 测试计划（五级标题+表格内容）
│   │   │   └── test_case/             # 测试用例目录
│   │   │       ├── 001-case-name.yaml
│   │   │       └── 002-case-name.yaml
│   │   └── 002-item2/                 # 测试项2
│   │       ├── plan.yaml
│   │       └── test_case/
│   └── 002-module/                    # 该指标涉及的模块2
│       ├── metadata.yaml
│       └── 001-item1/
│           └── plan.yaml

│   ├── 002-metric.yaml
│   └── 001-module/
│       └── 001-item1/
└── README.md                           # 本文件
```

## 🎯 组织原则

### 三层结构设计

data 目录采用**指标-模块-测试项**的三层结构：

```
测试指标 (Test Metric)
  └── 模块 (Module)
      └── 测试项 (Test Item)
          └── 测试用例 (Test Case)
```

**对应到测试计划文档的章节结构**：
```
4.2 计划执行的测试
  ├─ 4.2.1 测试指标1              ← 三级标题（来自 metric.yaml 的 content）
  │   ├─ 4.2.1.1 模块1            ← 四级标题（来自 metadata.yaml 的 MODULE_NAME）
  │   │   ├─ 4.2.1.1.1 测试项1（标识）  ← 五级标题（来自 plan.yaml）
  │   │   │   └─ 表11: 测试项详细信息
  │   │   └─ 4.2.1.1.2 测试项2（标识）
  │   │       └─ 表12: 测试项详细信息
  │   └─ 4.2.1.2 模块2
  └─ 4.2.2 测试指标2
```

### 层次说明

#### 1. 测试指标层 (Test Metric)
- **目录命名**：`{编号}-test-metric/`（如 `001-test-metric/`）
- **编号规则**：从 001 开始递增
- **作用**：定义测试的高层次分类或验收指标
- **对应文档**：测试计划 4.2 章节的三级子标题

#### 2. 模块层 (Module)
- **目录命名**：`{编号}-module/`（如 `001-module/`）
- **编号规则**：每个指标下的模块从 001 开始递增
- **作用**：将指标分解为具体的功能模块
- **对应文档**：测试计划 4.2 章节的四级子标题

#### 3. 测试项层 (Test Item)
- **目录命名**：`{编号}-item{name}/`（如 `001-item1/`）
- **编号规则**：每个模块下的测试项从 001 开始递增
- **作用**：定义具体的测试项，包含测试计划和测试用例
- **对应文档**：测试计划 4.2 章节的五级子标题 + 表格内容

## 📝 YAML 文件格式规范

### 测试指标定义文件 (XXX-metric.yaml)

定义测试指标的元信息，存放在指标目录下。

```yaml
index: 01                    # 指标编号
source: XX合同               # 来源（如合同名称、文档编号等）
content: 大规模数据存储      # 指标名称（会成为三级标题）
```

**必填字段**：
- `index` - 指标编号（用于排序）
- `source` - 来源描述
- `content` - 指标名称（会作为 4.2.x 章节的标题）

**生成效果**：
```
\subsubsection*{4.2.1 大规模数据存储}
```

### 模块元数据文件 (metadata.yaml)

定义模块的元信息，存放在模块目录下。

```yaml
MODULE_NAME: 大规模数据存储    # 模块名称（会成为四级标题）
MODULE_ID: LARGE_FILE_001      # 模块标识（可选，用于内部引用）
```

**必填字段**：
- `MODULE_NAME` - 模块名称（会作为 4.2.x.x 章节的标题）
- `MODULE_ID` - 模块标识（可选）

**生成效果**：
```
\paragraph*{4.2.1.1 大规模数据存储}
```

### 测试计划文件 (plan.yaml)

定义测试项的详细信息，存放在测试项目录下。

```yaml
测试项名称: 大文件存储1
标识: bigfilestorage1
测试要求: 测试项的测试要求
测试策略与方法:
  -测试策略: 测试策略描述
  -测试方法: 测试方法描述
假设与约束:
  -假设: 测试项的假设
  -约束: 测试项的约束
优先级: 高
测试终止条件: 测试项的终止条件
需求追踪关系: SRS-01
type: functional
metrics: 01-metric.yaml
```

**必填字段**：
- `测试项名称` - 测试项的名称
- `标识` - 测试项的唯一标识（建议使用英文/数字）
- `测试要求` - 测试的具体要求
- `测试策略与方法` - 包含测试策略和测试方法两个子字段
- `假设与约束` - 包含假设和约束两个子字段
- `优先级` - 测试优先级（高/中/低）
- `测试终止条件` - 测试结束的条件
- `需求追踪关系` - 关联的需求编号
- `type` - 测试类型（functional/interface/reliability）

**生成效果**：
```
\subparagraph*{4.2.1.1.1 大文件存储1（bigfilestorage1）}

{\normalsize
\begin{table}[H]
  ... 表格内容 ...
\end{table}
}
```

### 测试用例文件 (XXX-case-name.yaml)

定义具体的测试用例，存放在测试项的 `test_case/` 目录下。

```yaml
测试用例名称: 正常上传文件测试
标识: tc-upload-normal
测试用例综述: 验证用户能够成功上传大小为10MB的正常文件
用例初始化: 准备测试文件和测试环境
前提与约束: 用户已登录系统，文件格式符合要求
测试用例类型: 有效类
测试步骤:
  - 序号: 1
    输入及操作: 选择10MB的PDF文件，点击上传按钮
    期望结果: 文件上传成功，显示上传进度条
  - 序号: 2
    输入及操作: 等待上传完成
    期望结果: 显示"上传成功"提示，文件出现在列表中
测试用例终止条件: 上传完成或返回错误信息
测试结果判定准则: 文件成功上传到服务器，大小一致
测试用例执行结果: 待执行
设计人员: 张三
操作人员: 李四
测试人员: 王五
测试时间: 2025-01-06
```

**必填字段**：
- `测试用例名称` - 测试用例的名称
- `标识` - 测试用例的唯一标识
- `测试步骤` - 测试步骤列表（至少包含序号、输入及操作、期望结果）

## 🔧 如何添加数据

### 添加新的测试指标

1. **创建指标目录**
   ```bash
   cd data/
   mkdir 003-test-metric/
   ```

2. **创建指标定义文件**
   ```bash
   touch 003-test-metric/003-metric.yaml
   ```

3. **填写指标信息**
   ```yaml
   index: 03
   source: XX合同
   content: 数据血缘查询
   ```

4. **在指标下创建模块**
   ```bash
   mkdir 003-test-metric/001-module/
   ```

### 添加新的模块

1. **进入指标目录**
   ```bash
   cd data/001-test-metric/
   ```

2. **创建新模块目录**
   ```bash
   mkdir 002-module/
   ```

3. **创建模块元数据文件**
   ```bash
   touch 002-module/metadata.yaml
   ```

4. **填写模块信息**
   ```yaml
   MODULE_NAME: 小规模数据存储
   MODULE_ID: SMALL_FILE_001
   ```

### 添加新的测试项

1. **进入模块目录**
   ```bash
   cd data/001-test-metric/001-module/
   ```

2. **创建测试项目录**
   ```bash
   mkdir 002-item2/
   ```

3. **创建测试计划文件**
   ```bash
   touch 002-item2/plan.yaml
   ```

4. **填写测试项信息**（参考上面的 plan.yaml 格式）

5. **创建测试用例目录**
   ```bash
   mkdir 002-item2/test_case/
   ```

### 添加新的测试用例

1. **进入测试用例目录**
   ```bash
   cd data/001-test-metric/001-module/001-item1/test_case/
   ```

2. **创建测试用例文件**
   ```bash
   touch 003-new-case.yaml
   ```

3. **填写测试用例信息**（参考上面的测试用例格式）

## 📊 数据生成流程

### 从数据到文档

```
data/ 目录结构                    →  测试计划文档章节
────────────────────────────────────────────────────
001-test-metric/                 →  4.2.1 大规模数据存储 (三级标题)
├── 001-metric.yaml              →     (content 字段)
├── 001-module/                  →
│   ├── metadata.yaml            →  4.2.1.1 模块1 (四级标题)
│   └── 001-item1/               →     (MODULE_NAME 字段)
│       └── plan.yaml            →  4.2.1.1.1 测试项1（标识）(五级标题)
│                                 →  表11: 测试项详细信息
```

### 生成命令

```bash
# 构建测试计划文档（自动从 data 读取数据）
./scripts/build_test_plan.sh

# 输出文件
# - output/test_plan.pdf              (PDF 文档)
# - output/test_plan/chapters/        (LaTeX 源码)
```

## ⚠️ 注意事项

### 命名规范

- ✅ **正确**：`001-test-metric/` - 指标目录
- ✅ **正确**：`001-module/` - 模块目录
- ✅ **正确**：`001-item1/` - 测试项目录
- ✅ **正确**：`bigfilestorage1` - 使用英文标识
- ❌ **错误**：`test-metric-001/` - 编号应在前面
- ❌ **错误**：`001-测试项/` - 不要使用中文作为目录名
- ❌ **错误**：`大文件存储/` - 标识应使用英文

### YAML 格式

- ✅ 支持**中文冒号** `：` 和英文冒号 `:`（脚本会自动转换）
- ✅ 冒号后面建议有空格
- ✅ 列表项用 `- ` 开头
- ✅ 建议使用 UTF-8 编码

### 编号规则

- **指标编号**：从 001 开始，全局递增（001, 002, 003...）
- **模块编号**：每个指标下独立从 001 开始
- **测试项编号**：每个模块下独立从 001 开始
- **测试用例编号**：每个测试项下独立从 001 开始
- **文档标题编号**：自动生成（4.2.1, 4.2.1.1, 4.2.1.1.1）

### 数据完整性

- 每个指标目录必须包含 `*-metric.yaml` 文件
- 每个模块目录必须包含 `metadata.yaml` 文件
- 每个测试项目录必须包含 `plan.yaml` 文件
- 缺少必需文件会导致生成失败或跳过该条目
